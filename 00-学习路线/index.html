00学习路线 — 从零到专家

这是一条经过实战验证的5 阶段路线，覆盖从 C 语言基础到能够提交 LKML patch 的全部技能点。 每阶段都给出明确的知识检验点，避免"自我感觉良好但其实不会"的陷阱。

本路线的核心信念

内核学习的最大误区是"只读不练"。本路线强制要求：每读完一个概念，必须在 QEMU + GDB 中亲自验证。 没有动手验证的"理解"都是错觉。

总览：5 个阶段

5 阶段渐进式学习路线（不含已有 C/OS 基础的快速通道）

阶段一：基础准备（4~6 周）

1.1 C 语言深度

内核 C 与应用层 C 写法差异巨大，必须掌握以下"内核惯用法"：

/* 1. container_of — 通过成员指针得到结构体指针（链表精髓） */
#define container_of(ptr, type, member) ({          \
    const typeof(((type *)0)->member) *__mptr = (ptr); \
    (type *)((char *)__mptr - offsetof(type, member)); })

/* 2. 多行宏的 do {} while(0) 包裹技巧 */
#define SET_FLAG(x, f) do { (x)->flags |= (f); barrier(); } while(0)

/* 3. likely/unlikely — 分支预测提示 */
if (likely(p != NULL)) { ... }     // 编译器生成顺序流
if (unlikely(err == -EINVAL)) { ... } // 编译器把错误路径搬远

/* 4. 内联汇编 (GCC AT&T 语法) */
static inline unsigned long arch_local_irq_save(void) {
    unsigned long flags;
    asm volatile("pushfq; popq %0; cli" : "=rm"(flags) :: "memory");
    return flags;
}

/* 5. __attribute__ 修饰符 */
static int __init my_init(void);   // 放入 .init 段，启动后释放
static void __exit my_exit(void);   // 仅模块卸载时使用
static int data __read_mostly;     // 放入"读多"段，cacheline 友好
必须熟练（否则读源码处处碰壁）
  • 指针、函数指针、回调（`file_operations.read` 就是函数指针）
  • 位操作 / 位字段 / 掩码
  • 预处理宏（`#`、`##`、可变参宏）
  • GCC 扩展：`typeof`、`__builtin_*`、内联汇编
  • 链接脚本基础（`vmlinux.lds` 看不懂没关系，但要知道存在）

1.2 操作系统理论

无 OS 基础者必先补这些概念（不必精通，能画出框图即可）：

主题必懂概念检验方法
进程/线程PCB、状态机、上下文切换、线程模型用一张图说清楚 fork/exec/wait
调度FIFO、RR、CFS 直觉理解解释为什么 CFS 比 O(1) 好
虚拟内存分页、页表、TLB、缺页中断画出虚拟地址→物理地址
并发临界区、锁、死锁、原子操作写出死锁的 4 个必要条件
文件系统inode、目录、VFS 抽象解释一次 read() 全过程
IO阻塞 vs 非阻塞、同步 vs 异步区分 select/poll/epoll/io_uring
中断中断向量、上下半部、IRQ解释为什么不能在中断里 sleep

下面这些工具是"读 + 写 + 调试 + 分析"内核的必备品：

阶段二：Linux 0.11 精读（8~12 周）

为什么选 0.11 而不是 0.01？

0.01 是不完整的实验代码（连 shell 都跑不起来），0.11 是第一个能完整运行用户程序、自我托管编译的版本。 13990 行（不含注释），既小到可以完整读完，又大到包含所有 OS 核心概念。

8 周精读计划

周次主题对应源文件本周末检验：能否……
第 1 周启动流程boot/bootsect.s, boot/setup.s, boot/head.s解释 BIOS → 实模式 → 保护模式 → C 入口的每一跳？
第 2 周内核初始化init/main.c列出 start_kernel 中所有子系统的初始化顺序？
第 3 周内存管理mm/memory.c, mm/page.s从 0 开始画出 0.11 的段页式地址转换？
第 4 周进程与调度kernel/fork.c, kernel/sched.c把 copy_process 的每一步背下来？
第 5 周系统调用kernel/system_call.s, kernel/sys.c从 int 0x80 一路追到 sys_write 返回？
第 6 周信号与 IPCkernel/signal.c, kernel/exit.c说清 zombie 进程是怎么形成又怎么消失的？
第 7 周文件系统fs/* 全部从打开 /etc/passwd 一路追到磁盘块？
第 8 周设备驱动kernel/blk_drv/, kernel/chr_drv/解释 tty 行规范怎么处理回车？

阶段三：Linux 2.6 精读（8~12 周）

2.6.0 是现代内核框架成型的里程碑版本。读 2.6 时重点关注差异，不要重读已懂的部分。

0.11 → 2.6 对照学习

Linux 0.11 (已读)

  • 段页式内存 (基址 = pid × 64MB)
  • kernel/sched.c 简单时间片
  • fs/ 直接是 Minix FS
  • 无 SMP，关中断即同步
  • 固定 64 进程上限

Linux 2.6.0 (重点)

  • 纯页式 + mm_struct + VMA
  • kernel/sched.c O(1) 调度器
  • fs/ext2 + VFS 抽象层
  • SMP + spinlock/mutex/RCU
  • 动态进程表 + namespace 雏形

阶段四：专家级专题（10~16 周）

不再线性阅读，按兴趣专题深入。本指南后半段（10~15 章）即为此阶段服务：

  • CFS 调度器：vruntime、负载均衡、EAS
  • 容器内核机制：namespace、cgroup v2、OverlayFS
  • eBPF：现代内核可编程性
  • 中断子系统：IRQ、softirq、threaded IRQ
  • 启动流程深入：UEFI、KASLR、ACPI
  • 调试与性能：ftrace、perf、KASAN

阶段五：贡献社区

5.1 找一个突破口

不要一上来就想"修复某个大 bug"。从这些低门槛切入：

  • kernelnewbies.org / KernelJanitors：有专门的入门 issue 列表
  • 修复 checkpatch.pl 警告：纯文本编辑，提交容易
  • 文档错别字 / 过时信息：低风险
  • 把过时的 API 调用迁移到新 API：机械工作，欢迎度高

5.2 邮件 patch 流程

# 1. 配置 git
git config --global user.name "Your Name"
git config --global user.email "you@example.com"
git config --global sendemail.smtpencryption tls
git config --global sendemail.smtpserver smtp.gmail.com
git config --global sendemail.smtpuser "you@gmail.com"

# 2. 创建 patch
git format-patch -1 HEAD --subject-prefix="PATCH"

# 3. 找该子系统的 maintainer 和邮件列表
./scripts/get_maintainer.pl 0001-my-patch.patch

# 4. 发送
git send-email --to=maintainer@kernel.org \
               --cc=linux-kernel@vger.kernel.org \
               0001-my-patch.patch

每日学习节奏（推荐）

2~3 小时/天的高效安排
  1. 0:00 ~ 0:20 — 复习昨天笔记，3 分钟内能讲出"昨天学了啥"
  2. 0:20 ~ 1:30 — 精读源码（不超过 200 行/天，多了消化不动）
  3. 1:30 ~ 2:00 — 画图：当天阅读涉及的数据结构、流程图
  4. 2:00 ~ 2:30 — 在 QEMU 中验证（设断点、打印变量）
  5. 2:30 ~ 3:00 — 整理笔记（用自己的话复述）
三大常见误区
  1. "只读不练"：读完 100 章不如调试明白一个函数
  2. "追新版"：直接读 6.x 内核 90% 概率挫败放弃，从 0.11 开始
  3. "东学西学"：今天 fork 明天 TCP 后天驱动，必须按子系统专精
