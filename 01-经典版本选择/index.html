01经典版本选择 — 为什么是 0.11 + 2.6

本章回答一个学习者最关心的问题："3000 万行代码的内核，我到底该读哪个版本？"

一句话答案

主读 Linux 0.11（14k 行，可全读完），辅读 Linux 2.6.0（80 万行，对照学现代框架），关注 5.x/6.x 的特定子系统（专题学习）。

为什么不直接读最新版?

版本发布年代码行数读完时间估计适合阶段
0.011991~10,000—残缺品，不推荐
0.111991~14,0002~3 月可读完★ 入门首选
0.991993~50,000—已无人维护资料
1.01994~170,000太长跳过
2.4.02001~3,000,000不可能查阅
2.6.02003~5,900,000专题读，3~6 月★ 现代框架对照
3.x2011~15,000,000太长专题
5.x2019~28,000,000太长专题
6.x2022~33,000,000+太长专题

为什么 Linux 0.11 是黄金切入点

  1. 麻雀虽小五脏俱全：进程、内存、文件系统、TTY、磁盘 IO 全部有
  2. 线性结构清晰：没有 RCU、没有 SMP、没有大量抽象层包装
  3. 能跑能调：QEMU 上 1 秒启动，GDB 单步无障碍
  4. 中文资料完备：赵炯《Linux 内核完全注释》逐行讲解
  5. 核心概念全部出现：fork、调度、缺页、syscall、缓冲区、tty 行规范……

Linux 0.11 源码目录结构

linux-0.11/
├── boot/         # 引导：bootsect.s + setup.s + head.s (实模式→保护模式)
├── init/         # main.c (内核入口、所有子系统初始化)
├── kernel/       
│   ├── sched.c       # 调度器（仅 ~300 行!）
│   ├── fork.c        # 进程创建
│   ├── exit.c        # 进程退出
│   ├── signal.c      # 信号机制
│   ├── system_call.s # 系统调用入口（汇编）
│   ├── traps.c       # 异常处理
│   ├── blk_drv/      # 块设备驱动 (硬盘、软盘、ram disk)
│   ├── chr_drv/      # 字符设备驱动 (tty、串口、键盘)
│   └── math/         # 数学协处理器仿真
├── mm/           # 内存管理
│   ├── memory.c      # 页面分配、缺页处理
│   └── page.s        # 缺页异常入口（汇编）
├── fs/           # 文件系统 (Minix FS)
│   ├── inode.c       # inode 管理
│   ├── buffer.c      # 缓冲块管理
│   ├── file_table.c  # 文件表
│   ├── namei.c       # 路径解析
│   ├── read_write.c  # 读写
│   └── ... 等 20+ 个文件
├── lib/          # 内核内 C 库 (close, exit, dup ...)
├── include/      # 头文件
└── tools/        # build 工具

为什么 2.6.0 是现代内核的"创世版"

2.6 在 2003 年发布，相对 2.4 是一次大规模框架重构，奠定了至今未变的核心架构：

子系统2.4 (旧)2.6 (现代框架)之后版本
调度器O(n) 遍历O(1) 调度器2.6.23 起换成 CFS
内存简单NUMA、反向映射 (rmap)沿用
文件系统VFS 较简单VFS 重构 + sysfs沿用
设备模型各自为政kobject / sysfs 统一沿用
线程LinuxThreadsNPTL (futex 基础)沿用
同步仅 spinlock/semRCU 大量引入沿用并扩展
抢占非抢占CONFIG_PREEMPT 可选沿用

    long state;          // 状态
    long counter;        // 剩余时间片
    long priority;
    long signal;
    struct sigaction sigaction[32];
    long blocked;
    int exit_code;
    unsigned long start_code, end_code, end_data;
    unsigned long brk, start_stack;
    long pid, father, pgrp, session, leader;
    unsigned short uid, euid, suid;
    unsigned short gid, egid, sgid;
    long alarm;
    long utime, stime, cutime, cstime, start_time;
    unsigned short used_math;
    int tty;
    unsigned short umask;

Linux 6.x task_struct (~400 字段)

struct task_struct {
    /* 状态、栈、调度 */
    unsigned int __state;
    void *stack;
    int on_cpu, prio, static_prio, normal_prio;
    struct sched_entity se;   // CFS 实体
    struct sched_rt_entity rt; // RT 实体
    struct sched_dl_entity dl; // Deadline 实体
    
    /* 内存 */
    struct mm_struct *mm, *active_mm;
    
    /* PID 命名空间 (容器关键) */

    struct nsproxy *nsproxy;
    
    /* 文件、信号、IPC */

    struct fs_struct *fs;
    struct signal_struct *signal;
    
    /* SMP、CPU 亲和性、cgroup */
    cpumask_t cpus_mask;
    struct css_set *cgroups;
    
    /* perf、ftrace、tracing 钩子 */
    struct perf_event_context *perf_event_ctxp[];
    
    /* ……还有 ~300 个字段 */
};

推荐阅读策略

"对照阅读法"

读 2.6 时，每打开一个文件，先回忆 0.11 对应文件做了什么，再看 2.6 在此基础上加了什么。这样不会迷失在抽象层里。

示例：读 2.6/kernel/sched.c 时，先回忆 0.11/kernel/sched.c 的简陋调度，再看 2.6 的 O(1) 是如何分两个 priority array 实现的。

三种学习者的最优策略

背景推荐策略
毫无 OS 基础先读《操作系统精髓》→ 再 0.11 精读 → 再 2.6 对照
有 OS 课程基础直接 0.11 精读 (2 个月) → 2.6 专题 → 选修 5.x/6.x 专题
已写过驱动跳过 0.11 部分；2.6 文件系统 + 网络 + 内存 直接深入
