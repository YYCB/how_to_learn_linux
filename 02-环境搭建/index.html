02环境搭建 — QEMU + GDB 全套工具链

本章目标：在 30 分钟内 让你能够在 QEMU 中启动 Linux 内核，并用 GDB 在 start_kernel() 处下断点。

为什么必须用 QEMU？

真机调试内核 → 一旦 crash 整机重启，调试效率为 0。QEMU 是软件模拟器，crash 只是退出进程，可以无限次重启；更重要的是 QEMU 提供 gdbserver 接口，让 GDB 可以像调试用户程序一样调试内核。

2.1 安装基础工具

# Ubuntu / Debian
sudo apt install -y \
    build-essential gcc-multilib \
    qemu-system-x86 qemu-utils \
    gdb gdb-multiarch \
    bison flex libelf-dev libssl-dev \
    libncurses-dev bc rsync cpio \
    git wget

# macOS (M1/M2 用 brew)
brew install qemu gdb x86_64-elf-gcc

# Fedora
sudo dnf install qemu gdb ncurses-devel openssl-devel elfutils-libelf-devel

2.2 Linux 0.11 环境

# 1. 克隆带注释的版本
git clone https://github.com/karottc/linux-0.11.git
cd linux-0.11

# 2. 编译（需要老 gcc，可用 Docker）
docker run -it --rm -v $(pwd):/work tinyminded/gcc4 \
    bash -c "cd /work && make"

# 3. QEMU 启动
qemu-system-i386 -m 16M \
    -boot a -fda Image \
    -hda hdc-0.11-new.img \
    -nographic -append "console=ttyS0"

# 4. GDB 调试启动: 加 -s -S
qemu-system-i386 -m 16M -boot a -fda Image \
    -hda hdc-0.11-new.img -s -S &

# 另一终端
gdb
(gdb) target remote :1234
(gdb) file tools/system     # 加载符号
(gdb) break main             # 在 init/main.c:main 下断
(gdb) continue

2.3 现代内核 (5.x/6.x) 环境

构建最小可调试内核

# 1. 下载源码
wget https://cdn.kernel.org/pub/linux/kernel/v6.x/linux-6.6.tar.xz
tar xf linux-6.6.tar.xz && cd linux-6.6

# 2. 默认配置 + 开启调试选项
make defconfig
./scripts/config -e DEBUG_INFO \
                 -e DEBUG_INFO_DWARF4 \
                 -e GDB_SCRIPTS \
                 -e DEBUG_KERNEL \
                 -e FRAME_POINTER \
                 -d RANDOMIZE_BASE        # 关闭 KASLR (调试方便)

# 3. 编译 (i7 ~5 分钟)
make -j$(nproc) bzImage modules

# 4. 构造 initramfs
mkdir -p initramfs/{bin,sbin,etc,proc,sys,dev}
wget https://busybox.net/downloads/binaries/1.35.0-x86_64-linux-musl/busybox -O initramfs/bin/busybox
chmod +x initramfs/bin/busybox

cat > initramfs/init <<'EOF'
#!/bin/busybox sh
/bin/busybox --install -s
mount -t proc proc /proc
mount -t sysfs sysfs /sys
mount -t devtmpfs devtmpfs /dev
exec /bin/sh
EOF
chmod +x initramfs/init

(cd initramfs && find . | cpio -o -H newc | gzip > ../initramfs.img)

# 5. QEMU 启动
qemu-system-x86_64 -kernel arch/x86/boot/bzImage \
    -initrd initramfs.img \
    -append "console=ttyS0 nokaslr" \
    -nographic -m 512M

2.4 GDB 调试现代内核

# 启动 QEMU + 等待 GDB
qemu-system-x86_64 -kernel arch/x86/boot/bzImage \
    -initrd initramfs.img -append "console=ttyS0 nokaslr" \
    -nographic -m 512M -s -S

# 另一终端
gdb vmlinux
(gdb) target remote :1234
(gdb) hbreak start_kernel
(gdb) continue

# 内核到达 start_kernel 时停住，从此可单步、看变量
(gdb) bt
(gdb) p init_task
(gdb) p init_task->comm
(gdb) lx-ps              # 内核自带 GDB 脚本：列出所有进程
(gdb) lx-dmesg           # 显示内核日志
(gdb) lx-list-check ...  # 检查链表完整性

2.5 VS Code 集成

把内核源码当成普通项目用 VS Code 打开，配合 clangd 可获得近乎"工业级"的代码导航：

# 1. 安装 clangd 扩展，然后：
make clean
# 生成 compile_commands.json (clangd 必需)
make -j$(nproc) compile_commands.json   # 内核内置目标

# 2. .vscode/settings.json
{
  "clangd.arguments": [
    "--compile-commands-dir=.",
    "--background-index",
    "--header-insertion=never"
  ]
}

效果：F12 跳转定义、shift+F12 找所有引用、hover 显示函数签名 — 全部对内核源码生效。

2.6 高阶工具链

KGDB
真机内核调试

通过串口 / 网络在真机上调试内核 (不靠 QEMU)。开发驱动时常用。

CRASH
崩溃 dump 分析

配合 kdump 收集的 vmcore 文件，事后分析内核 panic 原因。

FTRACE
函数追踪

/sys/kernel/debug/tracing，无侵入跟踪任意函数调用。

PERF
性能采样

perf record / report / top，分析热点函数、CPU 周期。

BPFTRACE
动态追踪 DSL

用 awk 风格脚本写动态探针。一行命令搞定复杂分析。

QEMU-IMG
磁盘镜像工具

创建、转换、查看虚拟磁盘镜像。
