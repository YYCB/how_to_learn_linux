12eBPF — 内核可编程性革命

eBPF (extended Berkeley Packet Filter) 是过去十年 Linux 内核最重大的创新。它把内核从"封闭的固件"变成可在运行时动态扩展的执行引擎。

12.1 eBPF 是什么

一句话理解

eBPF 让你把一段 C 代码编译成字节码，注入到内核里的某些"挂载点"运行，不需要修改内核源码，不需要装内核模块。 代码受严格验证 (Verifier) 不会让内核崩溃。

12.4 完整例子：统计每个命令的 syscall 次数

/* count_syscall.bpf.c */
#include <vmlinux.h>
#include <bpf/bpf_helpers.h>
#include <bpf/bpf_tracing.h>

struct {
    __uint(type, BPF_MAP_TYPE_HASH);
    __uint(max_entries, 1024);
    __type(key, char[TASK_COMM_LEN]);
    __type(value, u64);
} count_map SEC(".maps");

SEC("tp/raw_syscalls/sys_enter")
int on_syscall(struct trace_event_raw_sys_enter *ctx) {
    char comm[TASK_COMM_LEN];
    bpf_get_current_comm(&comm, sizeof(comm));

    u64 *val = bpf_map_lookup_elem(&count_map, &comm);
    if (val) {
        __sync_fetch_and_add(val, 1);   // 原子加
    } else {
        u64 one = 1;
        bpf_map_update_elem(&count_map, &comm, &one, BPF_ANY);
    }
    return 0;
}

char LICENSE[] SEC("license") = "GPL";

# 用 bpftrace 一行完成同样功能
bpftrace -e 'tracepoint:raw_syscalls:sys_enter { @[comm] = count(); }'

# 5 秒后 Ctrl+C 看结果
@[bash]: 1234
@[nginx]: 50000
@[systemd]: 87

12.5 bpftrace — 内核版 awk

# 跟踪 open 系统调用
bpftrace -e 'tracepoint:syscalls:sys_enter_openat {
    printf("%s opened %s\n", comm, str(args->filename));
}'

# 统计 read 延迟分布
bpftrace -e '
kprobe:vfs_read { @start[tid] = nsecs; }
kretprobe:vfs_read /@start[tid]/ {
    @ns = hist(nsecs - @start[tid]);
    delete(@start[tid]);
}'

12.6 BCC、libbpf、CO-RE

工具特点适用场景
bpftrace一行 DSL临时排查
BCCPython + 嵌入 C复杂工具（运行时编译，依赖 LLVM）
libbpf + CO-RE纯 C + 提前编译生产环境（推荐）
CO-RE (Compile Once, Run Everywhere)

历史上 BCC 工具每次运行都要在目标机编译，需要内核 headers。 CO-RE 通过 BTF (BPF Type Format) 信息，让 BPF 程序一次编译，跑遍所有有 BTF 的内核（4.18+ 普遍支持）。
