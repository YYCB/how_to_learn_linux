13中断与异常子系统

中断是CPU 与外界沟通的唯一异步通道。本章从硬件中断向量讲到 threaded IRQ、IPI、softirq 全套机制。

13.1 为什么有中断

没中断 → CPU 必须轮询外设是否就绪 → 99% 时间浪费。中断让 CPU 在外设事件发生时被动接到通知，期间可以做别的事。

13.2 中断向量与 IDT (x86)

向量号类型例子
0~31异常 (内部)0=DIV/0, 6=#UD, 13=#GP, 14=#PF
32~47传统 IRQ (PIC)32=timer, 33=keyboard
32~255APIC / MSI现代 PCI 设备动态分配
0x80软中断 (老)int 0x80 = 系统调用 (i386)
NMI不可屏蔽看门狗、硬件错误
/* arch/x86/kernel/idt.c — IDT 表项 */
static const __initconst struct idt_data def_idts[] = {
    INTG(X86_TRAP_DE,    asm_exc_divide_error),     // vec 0
    INTG(X86_TRAP_DB,    asm_exc_debug),            // vec 1
    INTG(X86_TRAP_BP,    asm_exc_int3),             // vec 3 (int3 断点)
    INTG(X86_TRAP_PF,    asm_exc_page_fault),       // vec 14 缺页
    INTG(X86_TRAP_GP,    asm_exc_general_protection),
    /* ... */
};

13.4 softirq vs tasklet vs workqueue

对比softirqtaskletworkqueue
类型数固定 10 种可动态创建可动态创建
上下文软中断软中断进程
可 sleep否否是
并发同类可在不同 CPU 并发同类只在一个 CPU完全并发
典型用户网络/定时器逐步淘汰多数延后处理首选
/* workqueue 使用示例 */
static void my_work_fn(struct work_struct *w) {
    // 进程上下文! 可以 sleep、kmalloc(GFP_KERNEL)
    msleep(100);
    do_slow_io();
}

DECLARE_WORK(my_work, my_work_fn);

/* 中断里触发 */
schedule_work(&my_work);           // 加入 system_wq

/* 或专用 workqueue */
struct workqueue_struct *wq = alloc_workqueue("my_wq", WQ_UNBOUND, 0);
queue_work(wq, &my_work);

/* 延后执行 */
DECLARE_DELAYED_WORK(dw, my_work_fn);
schedule_delayed_work(&dw, msecs_to_jiffies(500));

13.5 threaded IRQ — 整个中断处理跑在线程里

实时系统 (PREEMPT_RT) 几乎所有中断都改为 threaded IRQ，因为传统 ISR 不能被抢占，破坏延迟保证：

/* 注册 threaded IRQ */
/* primary = 快速 ack;  thread_fn = 实际处理逻辑在线程里 */
request_threaded_irq(irq,
                     primary_handler,   // 也可为 NULL
                     threaded_handler,  // 进程上下文，可 sleep!
                     IRQF_ONESHOT,
                     "my-dev", dev);
